# Pub Quiz Powerhouse 3.3.0-alpha.1 — Dual Experience Foundations

**Development build — DO NOT deploy over the live v3.2 Render service yet.**

## What's implemented in this alpha

- New experience chooser in Setup: **Classic Pub Quiz** and **TV Game Show**, distinct from the existing *teams vs head-to-head* setting.
- Classic choice/typed questions: all correct teams receive the configured question points, irrespective of answer speed. Classic phone answers can be revised until the host closes answers.
- TV Game Show choice/typed questions: all correct teams receive base points; first correct +2, second correct +1. Buzzer-only rounds retain a first-correct-wins policy.
- Explicit host reveal before awarding points in new experiences. The Next/Skip actions refuse to silently award a submitted question without revealing it. All-wrong questions can proceed for zero points.
- Local state upgraded to version 2 with `settings.experience` and a per-question award ledger. A repeated award is blocked for already-awarded question IDs; Undo removes the corresponding ledger entry when undoing a recorded scoring group.
- Saved v3.2 sessions with no experience field load as **Legacy v3.2** so existing scoring and scores are not reinterpreted. Switching experience after a game has begun requires confirmation and a score reset.
- The phone's public state now identifies the experience and hides marks until the answer is revealed. New modes rank remote submissions by the host's receipt order, not device-reported timestamps.
- All v3.2 avatars, sounds, quizzes, Windows start files and Render support remain included.

## Important limits — still to implement before release

1. Full, separate **PREVIEW → OPEN → LOCKED → REVEALED → MARKED → AWARDED → NEXT** lifecycle with comprehensive undo/correction UI and no-score finalisation.
2. Persisted per-question submissions for revisiting previously scored questions; currently the ledger prevents re-awarding but the detailed question submission history isn't restored when navigating backwards.
3. Clearer host controls for changing Classic answers without phones, and accurate offline/late submission acknowledgements.
4. Protection against a malicious phone claiming another team's ID; this is inherited from v3.2 and needs a dedicated connection-authentication pass.
5. Full browser/device testing and Render preview. The graphical browser in the development environment refused local navigation, so UI testing is **not** claimed as passed.
6. Legacy startup, relay integration and Render build validation. Dependencies were unavailable in the build environment and the original relay test could not execute; the pure scoring tests and JavaScript syntax check did pass.

## Safe test procedure (Windows)

1. Extract this ZIP into a NEW folder. Do not overwrite your v3.2 working directory.
2. Open that folder and double-click `start.bat` (first launch may install dependencies).
3. Open the quizmaster Setup; select Classic and choose a multiple-choice round. Join 3–4 teams and answer using phones.
4. Close answers, reveal, and award points; check that all correct teams get the same points, then change to Show using a fresh quiz and check 3/2/1 for four correct teams.
5. Refresh the quizmaster, verify the scores persist, and check attempts to rescore an already-awarded question are blocked.
6. Report any unexpected behaviour. Do not merge the feature branch or auto-deploy this version to Render until accepted.
