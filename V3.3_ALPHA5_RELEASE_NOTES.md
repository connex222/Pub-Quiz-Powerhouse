# Pub Quiz Powerhouse v3.3 Alpha 5 — Quizmaster Approval for Phones

**Release:** Development alpha 5 (NOT approved for live Render production). Built on the validated Alpha 4 code from the `feature/v3.3-dual-experience` branch.

## What changed

- **Phone join requests need the quizmaster's approval by default.** Scanning the QR code does not immediately grant control of an existing team.
- The **Host** and **Setup** pages display a prominent **Phone join requests** panel with **Approve** and **Reject** buttons.
- **No new team is created until a quizmaster approves it.** Hosts can still turn off the ability to create new teams.
- Phones now display **Waiting for quizmaster approval**, with a **Cancel request** button.
- **Existing approved phones** can reconnect to the same team without submitting a second request while their host-side session is active.
- Pending requests can be cancelled, are automatically refreshed by the phone if still awaiting approval, and expire from the host queue after two minutes unless renewed.
- **Trusted home mode:** The quizmaster can uncheck **Quizmaster must approve phones before they join** in Setup if they deliberately want the previous direct-join behaviour. This is less secure.
- Authentication and server-side team binding introduced in Alpha 4 remain in place; the relay now accepts authenticated cancellation events.

## How to test safely

1. Extract this ZIP to a **new folder** outside your working v3.2 installation.
2. On Windows, double-click `start.bat` (first run requires internet to install packages).
3. On the quizmaster device, select **From their phones** in Setup. Keep **Quizmaster must approve phones** checked.
4. Scan the QR code on one phone and select an existing team. The phone should display **Waiting for quizmaster approval**.
5. The Host or Setup tab should now show a join-request card. Click **Approve**; verify the phone can play.
6. Join another phone and click **Reject**; verify it remains unable to buzz for that team.
7. Test a new team request and cancel it from the phone, then test approval of a new team.
8. Refresh an approved phone and confirm it reconnects to its original team. Run both Classic and TV Game Show rounds.
9. Test a brief disconnection and a host refresh. Record anything that fails.

## Known limitations

- Security is a **host approval check**, not a unique authenticated human identity. A person with a copied phone session credential could impersonate that phone. Do not share phone browser storage.
- The **host browser** still contains the authoritative quiz state. A Render instance restart does not persist the relay's room and approval records. Previously-approved phones may need approval again after host/server state is lost.
- Pending requests live in quizmaster memory and are not written to permanent storage. The phone retries them if still connected; if disconnected or closed it must rejoin.
- The multiplayer relay is designed for **one Render instance**. Multi-instance deployment and production failover are not supported.
- Neutral Idle avatar images were not provided; the existing Correct-as-idle fallback remains.
- **Do not merge Alpha 5 to `main` or deploy over the live v3.2 service until real-device acceptance tests pass.**
