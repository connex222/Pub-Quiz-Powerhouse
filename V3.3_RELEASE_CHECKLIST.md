# Pub Quiz Powerhouse v3.3 — Release Acceptance Checklist

This checklist applies to `3.3.0-rc.1` (`release/v3.3-rc1`), **not** the previously tested Alpha 7 build. The owner should record the actual results before release.

## A. Source and installation

- [ ] Confirm `main` still points to the working v3.2 game (leave it unchanged).
- [ ] RC1 branch deployed to a **separate** Render staging service.
- [ ] Render build completed and staging website/`/tv` both open.
- [ ] Windows `run-release-checks.bat` prints `ALL TESTS PASSED (LOCAL)` on this RC1 ZIP and generates `LIVE_TEST_RESULTS.txt`.
- [ ] Confirm `package.json` and `package-lock.json` are both `3.3.0-rc.1`.
- [ ] Verify all 24 identities/72 avatar assets and supplied audio exist.

## B. Real-device smoke test on RC1 staging

- [ ] Quizmaster opens host; two phones join with approval; TV displays correct room.
- [ ] Classic question: both correct scores are equal; no answer leaked before reveal.
- [ ] Classic correction: reopen marking, re-award, no duplicate or lost earlier points.
- [ ] Game Show buzzer: first caller gets exclusive turn; wrong caller cannot retry; second caller scores.
- [ ] Timer expiration rejects late buzzer; skipped question finalises with no unearned score.
- [ ] Phone briefly disconnected/reconnected without duplicate team; TV still follows host.
- [ ] Finish quiz: correct winner, Win portrait, scores, presentation and sound.
- [ ] Render application logs show no unhandled exceptions during the smoke test.

## C. Final sign-off

- [ ] Record known limitation: no durable server-side recovery of quizmaster browser data.
- [ ] Save RC1's commit SHA, test results and prior production deployment ID or commit SHA.
- [ ] Confirm production Render remains wired to `main`, not the RC branch.
- [ ] Owner expressly approves production promotion.
- [ ] Only then merge reviewed RC1 into `main`; verify deployment and do another quick live check.
