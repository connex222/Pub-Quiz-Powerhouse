## What this candidate contains

RC1 freezes the successfully tested Alpha 7 functionality. **No gameplay, multiplayer relay, or avatar asset changes were intentionally made for RC1.** Changes are restricted to the package version and release documentation.

- **Classic Pub Quiz:** quizmaster pacing, equal correct-answer points, phone answers, typed answer entry, individual question finalisation, history and score correction.
- **TV Game Show:** simultaneous-answer speed awards, first-buzz exclusive turns, wrong-answer ineligibility, optional deductions, timer expiry, zero-correct-point finalisation and reversible scoring.
- **Multiplayer:** quizmaster-approved or rejected team joining, phone session protection, TV pairing and reauthentication after temporary disconnects.
- **Presentation:** 24 distinct characters with 72 valid WebP Correct/Wrong/Win images; preserved supplied sound library; winning-team presentation.

## Known operational limitations (accepted only for private games)

- **Browser-local authority:** quizmaster state and scores persist in their browser storage, not in a durable server database. A different device, deleted site storage, or hardware failure can lose quiz progress.
- **One server instance:** relay permissions and TV pairing live in memory. A restart may require devices to reauthenticate or pair again; one successful restart test is not an uptime guarantee. Multiple Render instances with no shared state are unsupported.
- **Real-time fairness:** first-buzz arbitration depends on arrival at the quizmaster, not synchronised hardware timing across different mobile networks.
- **Avatar idle fallback:** the Correct asset serves as the neutral portrait because no separate Idle art was supplied.
- **Acceptance scope:** two-phone/TV and an eight-question playthrough were reported. This is not long-duration/load testing of the maximum team count, all browser models, or every question format.

## Rollback / recovery

- Keep the current production GitHub `main` SHA and Render deployment identifiable before any eventual release.
- During testing, leave production unchanged. If RC1 fails on staging, switch staging back to `feature/v3.3-dual-experience` (Alpha 7), redeploy and record the failure.
- After an approved live deployment, use the prior production Render deploy or known-good `main` commit to roll back if necessary. Do not delete or overwrite quizmaster browser storage as a troubleshooting shortcut.
