# Pub Quiz Powerhouse v3.3 Alpha 7 — Relay Input Validation & Release Checks

**Status:** Development alpha. **Not approved for production.** Keep Render's live service on `main` (v3.2). Target for staging only: `feature/v3.3-dual-experience`.

## Release-blocking bug fixed

Eight Socket.io relay handlers previously used destructuring defaults, e.g. `({topic} = {})`. The default only protects against `undefined`; sending `null` would throw a TypeError. A hostile or malfunctioning client could potentially crash a Node process by emitting a `null` payload. All affected event handlers now normalise payloads to plain objects, rejecting invalid input rather than throwing. `pair-request` already did not destructure its input.

`test/relay-security.js` now exercises null, arrays, numbers and strings against each relay handler; `test/relay.js` also exercises null payloads over *real Socket.io* when dependencies are available.

## Known operational limits

- Host browser holds authoritative gameplay/score state; it can often restore from local storage, but is **not** a durable server backup.
- Render relays use in-memory phone permissions and TV pairing. A restart can invalidate them; re-pairing or rejoining may be necessary.
- Intended for a single Render instance. Scaling across instances without shared state is unsupported.
- No neutral Idle art in the supplied collection; Correct state remains the fallback.
